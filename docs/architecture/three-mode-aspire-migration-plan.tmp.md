# TEMPORARY — three-mode new-installation architecture migration plan

**Status:** working execution plan, 2026-10-23. Delete or archive only after all three modes have passed the release gates; not an operator runbook or claim of delivery.
**Authority:** [deployment-mode contract](./deployment-mode-contract.md) and [Private Cloud enterprise contract](./private-cloud-enterprise-architecture-contract.md). [Private Cloud evidence ledger](./private-cloud-design-status.md) describes what currently exists.

## Non-negotiable scope and safety

- New installations only. Keep existing Portable JSONL directories, Dedicated systemd installations, published Private Cloud Compose projects, PostgreSQL databases, S3 buckets, persistent volumes, credentials, and upgrade/restore commands unchanged. Do not silently import, switch or delete old data. A future opt-in legacy migration requires a **separate** approved design and independently verified backup/rollback.
- One Agent/Session lifecycle and logical Platform Runtime contract. Portable storage adapter: SQLite `state.sqlite` + local content-addressed object bytes. Dedicated and Private Cloud storage adapters: PostgreSQL (control and Runtime schemas/databases/roles) + S3 API for bytes. Local state, SDK handles, WebSocket connections and temporary provider tokens are rebuildable projections, not authority.
- Acknowledgement ordering: write and verify object bytes first, protect reference in transaction, persist event/queue admission before publish; failed admission may leak a reclaimable object but may never lose an acknowledged one. Track unknown external side effects with operation IDs and receipts; never assert exactly-once for non-idempotent third parties.
- Dedicated: Aspire AppHost is source of deployment graph; `aspire publish` produces reviewed Docker Compose for outside terminal/CI deployment. One active Runtime. Same-host PostgreSQL and PGSTY MinIO-compatible **SILO** container, with data volumes separate from ephemeral application containers. Bootstrap one local Owner and revocable Gateway session in control PostgreSQL. HTTPS edge/Ingress is the only exposed application endpoint. No in-Runtime self-deploy, blue/green or Supervisor in the new graph. No HA claim.
- Private Cloud: same Runtime PostgreSQL/S3 semantics, external OIDC, tenant isolation, production target of multi-node fencing and coordinated recovery. Local PostgreSQL and S3-compatible containers **are allowed in tests**; they do not prove an external HA service, multi-zone failover or enterprise Pilot acceptance.
- Pin and verify actual PostgreSQL, SILO, Node and Aspire versions and immutable image digests before deployment. PGSTY's current MinIO-compatible product is [SILO](https://silo.pgsty.com/compatibility/migration/), which replaces the former `pgsty/minio` image; verify licensing, S3 conditional requests, versioning/retention, policy boundaries, multipart, backups and real failure/recovery before committing to a supported digest. Never use a moving `latest` for production.
